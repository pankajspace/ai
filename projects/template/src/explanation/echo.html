How It Works#

The idea behind the starter demo, the request it sends, and the function calls that answer it.

1

Concept#

The Echo endpoint is the canonical starter pattern for every interactive feature card across the TechToday container projects:

  • Plain HTML, CSS & JS UI: index.html and main.js validate that the user has entered non-empty text before enabling the submit button and sending a JSON POST /echo request.
  • Environment Neutrality (PATH_PREFIX): At request time, app.py injects PATH_PREFIX into data-api-base on <body> so main.js works identically at http://localhost:8090/ locally and behind Nginx at https://app.techtoday.click/<project>/.
  • Isolated Feature Module: The Flask route handler parses the JSON body, delegates business logic to echo.py, and returns a structured {"result": ...} JSON payload.
2

Theory#

1. Reverse Proxy Path-Prefix Routing

Production traffic on EC2 passes through a shared Nginx reverse proxy without stripping the project prefix segment. Registering all routes on a Flask Blueprint mounted at url_prefix=PATH_PREFIX lets the exact same container image run at / locally and at /<project-slug> in production.

2. Two-Layer Sliding-Window Rate Limiting

Every mutating POST request passes through enforce_rate_limit() before reaching the route handler. When RATE_LIMIT_ENABLED=true on EC2, a SQLite-backed sliding window caps each client IP at 30 requests per hour and returns HTTP 429 with a Retry-After header when exceeded.

3. Deterministic Error Contracts

Empty inputs return HTTP 400 with {"error": "..."}, and unexpected runtime exceptions return HTTP 500 with the error message so callApi() in main.js can render a consistent error banner.

Code explanation#

Core Feature Module (src/python/echo.py)

src/python/echo.py is the reference starter feature module for the container template. It implements a pure-Python text transformation function with zero external dependencies so the project can be run and verified offline.

Main Functionality in echo(text: str) -> str

  • echo(text: str) -> str: Accepts a raw user message string text and returns an upper-cased confirmation string annotated with its character count:
    • Step ① (Clean and format message): Strips leading and trailing whitespace via cleaned = text.strip(), converts the cleaned string to uppercase with cleaned.upper(), computes its length with len(cleaned), and returns f"You said: {cleaned.upper()} ({len(cleaned)} characters)".
  • CLI Execution Block (if __name__ == "__main__":): Prompts for interactive terminal input with message = input("Enter a message to echo: ") and prints the result of echo(message) so the feature module can also be tested directly from the command line.

End-to-End Feature Flow

  1. A raw input string text is passed into echo(text) in src/python/echo.py.
  2. echo() strips surrounding whitespace to produce cleaned, converts the text to uppercase, and measures len(cleaned).
  3. The function formats and returns "You said: <UPPER> (<N> characters)" as the final output string.

echo.py#

src/python/echo.py

"""Starter feature: a dependency-free "echo" that transforms text.

This module exists so the template runs end to end without any API keys.
Replace it with your project's real feature modules (one module per feature,
each exposing a small function that ``app.py`` calls). Keeping features in
their own modules makes them easy to add, remove, or test in isolation.
"""


def echo(text: str) -> str:
    """Return a short, upper-cased confirmation of the input text.

    Args:
        text: The message to echo back.

    Returns:
        A formatted string echoing the input. Pure Python — no network or
        API keys — so it works offline and in CI.
    """
    # ① clean and format the message
    cleaned = text.strip()
    return f"You said: {cleaned.upper()} ({len(cleaned)} characters)"


if __name__ == "__main__":
    # Allow running this feature directly:  docker compose run --rm echo
    message = input("Enter a message to echo: ")
    print(echo(message))

app.py#

146 lines
src/python/app.py

Flask Blueprint server and route handler (echo_route) in src/python/app.py.

"""Flask server exposing the starter ``/echo`` endpoint.

Architecture notes
------------------
- All routes are attached to a Blueprint (``bp``) instead of directly to
  ``app``. This lets us register the entire Blueprint under a runtime URL
  prefix (``PATH_PREFIX``) without touching individual route strings.
- In local development PATH_PREFIX is empty, so routes are at "/", "/echo",
  etc. In production Nginx forwards ``/<project-name>/...`` traffic to the
  container and PATH_PREFIX is set to "/<project-name>", keeping every URL
  consistent.
- flask-cors adds ``Access-Control-Allow-Origin: *`` headers so the HTML
  page can call the API even if it is served from a different origin during
  development.

To add a feature: create a module under ``src/python/`` (see ``echo.py``), import
its function here, and add a matching ``@bp.route(...)`` handler.
"""

import os
from pathlib import Path

from flask import Blueprint, Flask, jsonify, request
from flask_cors import CORS

from echo import echo
from rate_limiter import check_rate_limit

# ---------------------------------------------------------------------------
# Configuration
# ---------------------------------------------------------------------------

# PATH_PREFIX is set by the deployment environment (e.g. "/<project-name>") so
# the app works correctly behind an Nginx location block. Locally it is an
# empty string, which mounts all routes at the root.
PATH_PREFIX = os.environ.get("PATH_PREFIX", "")

# app.py lives in src/python, while index.html, css/, and js/ live in src/.
STATIC_DIR = Path(__file__).resolve().parents[1]
app = Flask(__name__, static_folder=str(STATIC_DIR))

# Allow cross-origin requests from any origin. In production you would
# restrict this to the specific front-end domain.
CORS(app)

# A Blueprint groups related routes. We register it once at the bottom with
# the runtime PATH_PREFIX, avoiding any hardcoded path strings in the routes.
bp = Blueprint("main", __name__)


@bp.before_request
def enforce_rate_limit():
    """Enforce strict 30 requests per hour limit on all POST endpoints."""
    # ① Only rate-limit mutating API requests
    if request.method == "POST":
        # ② Check whether this client has exceeded the hourly window
        blocked, msg, retry_after = check_rate_limit(
            request, max_requests=30, window_seconds=3600
        )
        if blocked:
            # ③ Return HTTP 429 with a Retry-After header when rate-limited
            resp = jsonify({"error": msg})
            resp.status_code = 429
            resp.headers["Retry-After"] = str(retry_after)
            return resp


# ---------------------------------------------------------------------------
# Routes
# ---------------------------------------------------------------------------


@bp.route("/")
def index():
    """Serve index.html, injecting the correct API base URL for the environment."""
    # ① Read the frontend HTML template from the static folder
    with open(os.path.join(app.static_folder, "index.html"), encoding="utf-8") as f:
        html = f.read()
    # ② Replace the empty data-api-base with the deployment path prefix
    # The HTML file ships with 'data-api-base=""' (empty = relative URL, works
    # locally). For production we replace it with the actual path prefix so
    # all fetch() calls in the browser target the right endpoint.
    html = html.replace('data-api-base=""', f'data-api-base="{PATH_PREFIX}"')
    # ③ Return the patched HTML response to the browser
    return app.response_class(html, mimetype="text/html")


@bp.route("/css/<path:filename>")
def css(filename):
    """Serve stylesheets from the src/css directory."""
    return app.send_static_file(os.path.join("css", filename))


@bp.route("/js/<path:filename>")
def js(filename):
    """Serve scripts from the src/js directory."""
    return app.send_static_file(os.path.join("js", filename))


@bp.route("/explanation/<path:filename>")
@bp.route("/info/<path:filename>")
def explanation(filename):
    """Serve the "how this demo works" explainer pages from src/explanation."""
    return app.send_static_file(os.path.join("explanation", filename))


@bp.route("/theory/<path:filename>")
def theory_pages(filename):
    """Serve the theory documentation pages from src/theory."""
    return app.send_static_file(os.path.join("theory", filename))


@bp.route("/echo", methods=["POST"])
def echo_route():
    """Echo back the posted message — the starter feature.

    Request body (JSON): ``{ "message": "<text>" }``
    Response (JSON):     ``{ "result": "<echoed text>" }``
    Error response:      ``{ "error": "<message>" }`` with HTTP 400 (missing
                         message).
    """
    # ① Parse the JSON payload and normalize the message string
    data = request.get_json(force=True)
    message = (data.get("message") or "").strip()
    # ② Validate at the boundary — return 400 immediately rather than processing
    # an empty message.
    if not message:
        return jsonify({"error": "A message is required."}), 400
    # ③ Delegate to the echo feature function and return JSON
    return jsonify({"result": echo(message)})


# ---------------------------------------------------------------------------
# Blueprint registration + server entry point
# ---------------------------------------------------------------------------

# Register all Blueprint routes under the optional path prefix. This single
# line is the only place where PATH_PREFIX is applied — every route above is
# written as a relative path (e.g. "/echo") and the prefix is prepended here.
app.register_blueprint(bp, url_prefix=PATH_PREFIX)


if __name__ == "__main__":
    # Run the development server. 0.0.0.0 makes the app reachable from outside
    # the container; port 5000 is mapped to the host port in docker-compose.yml.
    app.run(host="0.0.0.0", port=5000)

Quick revision#

Use this checklist to review the core full-stack and container architecture patterns demonstrated by the Echo starter template:

  1. Isolated Feature Modules: Keeping business logic in a dedicated module (src/python/echo.py) separate from HTTP routing (src/python/app.py) lets you test, replace, or run each feature independently via CLI or HTTP.
  2. Zero-Dependency Starter Baseline: Implementing the template's initial feature in pure Python without external API keys ensures Docker builds, health checks, and CI smoke tests succeed out of the box.
  3. Flask Blueprint Prefix Mounting: Attaching routes to bp = Blueprint("main", __name__) and registering it once with url_prefix=PATH_PREFIX allows the container to run at / locally and at /<project-name> behind an Nginx reverse proxy.
  4. Runtime data-api-base Injection: Replacing data-api-base="" with PATH_PREFIX when serving index.html lets frontend JavaScript construct environment-aware fetch() URLs without a build step.
  5. Two-Layer Sliding-Window Rate Limiting: The @bp.before_request hook inspects every POST request via check_rate_limit(), enforcing 30 requests per hour per client IP and returning HTTP 429 with a Retry-After header when exceeded.
  6. Fail-Fast Boundary Validation: Both setupCard() in main.js and echo_route() in app.py strip whitespace and reject empty messages immediately (returning HTTP 400 on the server) before invoking feature logic.
  7. Consistent JSON Envelope Contract: Successful calls return {"result": "..."} while errors return {"error": "..."} with appropriate HTTP status codes so a single callApi() helper can handle every card on the page.
