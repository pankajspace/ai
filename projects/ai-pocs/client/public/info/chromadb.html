Unit 1

How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

Unlike single-paragraph RAG, this service indexes a multi-file markdown knowledge base (docker-basics.md, compose-and-volumes.md, rag-notes.md) into a ChromaDB collection with source file and chunk metadata, then queries the top-K nearest chunks to answer user questions with source attribution.

2

Theory & Concepts#

  • Idempotent Upsert: Chunks are keyed by {filename}-chunk-{i} and upserted into ChromaDB so repeated queries reuse the indexed collection.
  • Metadata Attribution: Every vector stores source and chunk_index metadata so answers cite the exact markdown file.
  • Hybrid Chroma Client: Connects to a remote Chroma container when CHROMA_HOST is set, or transparently uses an in-process chromadb.EphemeralClient().
3

Request flow#

🧑 Browser ChromaDbCard.tsx sends POST /api/chromadb with { question, n_results }.
→
FastAPI route (main.py) chromadb_service(req) calls ask_chromadb_notes().
→
ChromaDB Query (02_chromadb.py) Embeds question with text-embedding-3-small → collection.query() returns top-K chunks + metadata.
→
🧑 Browser Shows grounded answer and retrieved markdown chunks with file citations.

FastAPI route handler for POST /api/chromadb.

@app.post("/api/chromadb", response_model=ChromaDbResponse)
def chromadb_service(req: ChromaDbRequest):
    if not req.question.strip():
        raise HTTPException(status_code=400, detail="Question cannot be empty")
    try:
        return ChromaDbResponse(**ask_chromadb_notes(req.question, req.n_results))
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
