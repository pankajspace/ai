Concept#

Joke Generator demonstrates one of the most practical architectural patterns in modern AI engineering: provider portability via OpenAI-compatible APIs. Instead of installing a proprietary SDK for every model host, this demo reuses the exact same openai.OpenAI client from the Travel Guide demo but points its base_url at Groq's high-speed inference cloud (https://api.groq.com/openai/v1).

By swapping only three configuration values — api_key (GROQ_API_KEY), base_url (GROQ_BASE_URL), and model (llama-3.3-70b-versatile) — the service routes requests to an open-weights LLaMA 3.3 70B model running on Groq's LPU (Language Processing Unit) hardware, generating topical jokes with sub-second latency.

2

Theory#

1. The OpenAI Chat Completions Standard as a Universal Contract

The OpenAI /v1/chat/completions JSON request/response specification has become the de facto industry wire protocol. Providers such as Groq, Google Gemini, Together AI, Fireworks, OpenRouter, Ollama, and vLLM all expose OpenAI-compatible endpoints. Writing against this single client interface prevents vendor lock-in and lets teams benchmark or fail over between cloud providers without rewriting application logic.

2. Open-Weights Models on Specialized Inference Hardware

While proprietary models (like GPT-4o) are tied to a single vendor, open-weights models (such as Meta's llama-3.3-70b-versatile or OpenAI's gpt-oss series) can be hosted by multiple competing inference providers. Groq runs these models on deterministic SRAM LPU chips, delivering hundreds of tokens per second — ideal for interactive user-facing features.

3. Decoupling Code from Provider Credentials

Notice that the message construction (system persona + user topic), the client.chat.completions.create() call, and the response extraction (response.choices[0].message.content) are line-for-line identical to the OpenAI Travel Guide service. Only the client initialization parameters change, loaded cleanly from .env.

4. Boundary Validation with Pydantic

The service defines JokeRequest and JokeResponse Pydantic schemas so FastAPI automatically validates incoming JSON payloads, supplies sensible defaults (topic="programming"), and documents the exact response contract in OpenAPI/Swagger.

02_chat_groq.py#

Groq Chat Completion Service - Joke Generator.

"""Groq Chat Completion Service - Joke Generator.

This service demonstrates using an alternative high-speed LLM provider (Groq)
via the OpenAI-compatible client interface:
1. Groq hosts open-weights models (such as LLaMA 3.3 70B) with high inference speed.
2. The standard `openai.OpenAI` client is reused by setting `base_url` to Groq's endpoint
   and authenticating with `GROQ_API_KEY`.
3. Pydantic models (JokeRequest, JokeResponse) validate and serialize API payloads.
"""

import os

from dotenv import find_dotenv, load_dotenv
from openai import OpenAI
from pydantic import BaseModel

# ---------------------------------------------------------------------------
# Configuration & Environment Setup
# ---------------------------------------------------------------------------
# Automatically locate and load the nearest .env file (e.g. at the repo or project root)
load_dotenv(find_dotenv())


# ---------------------------------------------------------------------------
# Request & Response Schemas (Pydantic)
# ---------------------------------------------------------------------------
class JokeRequest(BaseModel):
    """Input payload specifying the joke topic."""

    topic: str = "programming"


class JokeResponse(BaseModel):
    """Output payload containing the topic and generated joke."""

    topic: str
    joke: str


# ---------------------------------------------------------------------------
# Core Service Logic
# ---------------------------------------------------------------------------
def get_groq_joke(topic: str = "programming") -> str:
    """Tell a funny joke on a topic using Groq.

    Args:
        topic: Topic for the joke (defaults to "programming").

    Returns:
        A humorous joke generated by the Groq model.
    """
    # ① Initialize the OpenAI SDK client configured for Groq's base URL
    #   Read endpoint and model configuration (falling back to sensible defaults)
    client = OpenAI(
        api_key=os.getenv("GROQ_API_KEY"),
        base_url=os.getenv("GROQ_BASE_URL", "https://api.groq.com/openai/v1"),
        timeout=15.0,
    )
    model = os.getenv("GROQ_MODEL", "llama-3.3-70b-versatile")

    # ② Build the messages (system = persona, user = topic request)
    messages = [
        {"role": "system", "content": "You are a funny joke teller."},
        {"role": "user", "content": f"Tell me a joke about {topic}."},
    ]

    # ③ Call the chat completions endpoint with system persona and user topic
    response = client.chat.completions.create(model=model, messages=messages)

    # ④ Extract and return the joke text
    return response.choices[0].message.content or ""

FastAPI route handler for POST /api/joke (joke_generator) in server/main.py.

from dotenv import find_dotenv, load_dotenv
from fastapi import FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware

from services import (
    JokeRequest,
    JokeResponse,
    get_groq_joke,
)

# Load environment variables
load_dotenv(find_dotenv())

app = FastAPI(title="AI POCs API")

# Enable CORS for frontend requests
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.post("/api/joke", response_model=JokeResponse)
def joke_generator(req: JokeRequest):
    # ① Validate topic and call Groq joke generator service
    if not req.topic.strip():
        raise HTTPException(status_code=400, detail="Topic cannot be empty")
    try:
        return JokeResponse(topic=req.topic, joke=get_groq_joke(req.topic))
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
