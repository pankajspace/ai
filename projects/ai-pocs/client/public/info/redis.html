⚡ Redis Support Agent Memory#

⚡ Redis Support Agent Memory stores multi-turn conversation history per session_id with TTL expiry and runs an OpenAI tool-calling support agent with order lookup, refund policy, and refund estimation tools.

6 Topics • 4 Explainers • 2 Python Files in Full
Unit 1

How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

Production support agents must remember customer details (order IDs, names, prior questions) across turns while invoking tools for live order status and refund calculations. By keying conversation lists under support:session:{session_id} with a 1-hour TTL, the agent stays stateless at the process layer while preserving user sessions.

2

Theory & Concepts#

  • Session-Keyed Redis Lists: Uses RPUSH, LRANGE, DEL, and EXPIRE per session_id.
  • Function-Calling Loop: Iterates up to 4 rounds when the model emits tool_calls (get_order_status, lookup_refund_policy, estimate_refund).
  • Graceful Fallback: Uses Redis when REDIS_HOST is reachable, or falls back to an in-memory session store so demos work zero-config.
3

Request flow#

🧑 Browser RedisAgentCard.tsx sends POST /api/redis with { session_id, message }.
→
FastAPI route (main.py) redis_agent_service(req) calls run_redis_agent().
→
Session + Tools (03_redis.py) Loads history for session_id, runs OpenAI tool loop, and appends new turns with TTL.
→
🧑 Browser Shows agent response, invoked tools, and stored session message count.

@app.post("/api/redis", response_model=RedisAgentResponse)
def redis_agent_service(req: RedisAgentRequest):
    if not req.clear_session and not req.message.strip():
        raise HTTPException(status_code=400, detail="Message cannot be empty")
    try:
        return RedisAgentResponse(
            **run_redis_agent(req.session_id, req.message, req.clear_session)
        )
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
