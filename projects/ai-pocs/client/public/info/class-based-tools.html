How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

Class-Based Tools (Shared-Resource Pattern) solves a critical production engineering problem: how do multiple agent tools share state, database connection pools, or authenticated API clients without opening a brand-new connection on every single tool call or littering the codebase with global variables?

This demo encapsulates an inventory store (self.products) and two decorated methods — @tool def check_stock(self, product_id: str) and @tool def update_stock(self, product_id: str, quantity: int) — inside an InventoryTools class. Passing the bound methods tools=[inventory.check_stock, inventory.update_stock] to the Strands Agent lets a single request like "Update PROD-456 stock to 25 units, then confirm the new level" mutate state in one tool call and immediately verify the updated value in the next.

2

Theory & Concepts#

1. Why Standalone Tool Functions Break at Scale

If check_stock() and update_stock() are written as standalone functions that each call psycopg2.connect(...) inside their body, a 5-step agent turn opens and tears down 5 separate database connections — exhausting connection limits under concurrent traffic. Grouping related tools inside a class lets __init__() initialize a single connection pool, HTTP session, or state dictionary shared by every method.

2. Bound Methods and Automatic self Hiding

When you pass a bound method like inventory.check_stock to Agent(tools=[...]), Python binds the self parameter to the inventory instance, and Strands strips self from the generated JSON Schema. The LLM only sees product_id: str (and quantity: int for update_stock) — it never knows or cares that the tool is a method on a class.

3. Read-After-Write Verification in One Turn

Because both tools reference the exact same self.products dictionary, when the agent executes update_stock(product_id="PROD-456", quantity=25) on step 1 and check_stock(product_id="PROD-456") on step 2, the second call immediately sees 25 units. The response also returns a snapshot of current_inventory so the UI displays the live state after every run.

Class-Based Tools (Shared-Resource Pattern) Agent Service.

"""Class-Based Tools (Shared-Resource Pattern) Agent Service.

Demonstrates class-based tools that share state and resources across calls:
1. Architectural Problem: Individual tool functions opening separate DB connections flood databases.
2. The Solution: Group related tools in a class instance sharing single state/connection pool.
3. Class `InventoryTools`:
   - `check_stock(product_id: str)`
   - `update_stock(product_id: str, quantity: int)`
4. Handles multi-step state mutations within a single conversation session.
"""

import os

from dotenv import find_dotenv, load_dotenv
from pydantic import BaseModel
from strands import Agent, tool
from strands.models.bedrock import BedrockModel

# ① Load AWS credentials and Bedrock configuration from .env
load_dotenv(find_dotenv())


class ClassBasedToolsRequest(BaseModel):
    """Input payload for Class-Based Tools Agent."""

    query: str = "Update PROD-456 stock to 25 units, then confirm the new level"


class ClassBasedToolsResponse(BaseModel):
    """Output payload from Class-Based Tools Agent."""

    query: str
    response: str
    tool_calls: list[str]
    current_inventory: dict[str, int]


# ② Resolve the target Bedrock model identifier
model_id = os.getenv("BEDROCK_MODEL_ID", "amazon.nova-lite-v1:0")


class InventoryTools:
    """Grouped inventory tools sharing a single state."""

    def __init__(self):
        # Initialize the shared in-memory product store (represents a single DB connection pool)
        self.products = {
            "PROD-123": {"name": "Wireless Mouse", "quantity": 15, "price": 29.99},
            "PROD-456": {"name": "USB-C Cable",    "quantity": 0,  "price": 12.99},
            "PROD-789": {"name": "Laptop Stand",   "quantity": 8,  "price": 49.99},
        }

    @tool
    def check_stock(self, product_id: str) -> str:
        """Check the current stock level and price for a product.

        Args:
            product_id: The product ID to look up (e.g. 'PROD-123')
        """
        # Look up the product record in the shared self.products dictionary
        product = self.products.get(product_id)
        if not product:
            return f"Product {product_id} not found"
        return f"{product['name']}: {product['quantity']} units at ${product['price']}"

    @tool
    def update_stock(self, product_id: str, quantity: int) -> str:
        """Update product stock quantity.

        Args:
            product_id: The product ID to update
            quantity: New quantity to set
        """
        # Mutate the product quantity in the shared self.products store
        if product_id in self.products:
            self.products[product_id]["quantity"] = quantity
            return f"Updated {product_id} to {quantity} units"
        return f"Product {product_id} not found"


# ③ Instantiate InventoryTools once so stock updates persist across requests
inventory = InventoryTools()


def run_class_based_tools_agent(
    query: str = "Update PROD-456 stock to 25 units, then confirm the new level",
) -> dict:
    """Run the Class-Based Tools Agent."""
    # ④ Bind the shared instance's methods to the Strands Agent
    agent = Agent(
        model=BedrockModel(model_id=model_id),
        tools=[inventory.check_stock, inventory.update_stock],
    )

    # ⑤ Run the query against the shared InventoryTools instance
    response = agent(query)

    # ⑥ Collect every tool call the agent made from its message history
    tool_calls = [
        f"{block['toolUse']['name']}({block['toolUse']['input']})"
        for message in agent.messages
        for block in message["content"]
        if "toolUse" in block
    ]

    return {
        "query": query,
        "response": str(response),
        "tool_calls": tool_calls,
        "current_inventory": {pid: p["quantity"] for pid, p in inventory.products.items()},
    }

main.py#

FastAPI route handler for POST /api/class-based-tools (class_based_tools_service) in server/main.py.

from dotenv import find_dotenv, load_dotenv
from fastapi import FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware

from services import (
    ClassBasedToolsRequest,
    ClassBasedToolsResponse,
    run_class_based_tools_agent,
)

# Load environment variables
load_dotenv(find_dotenv())

app = FastAPI(title="AI POCs API")

# Enable CORS for frontend requests
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.post("/api/class-based-tools", response_model=ClassBasedToolsResponse)
def class_based_tools_service(req: ClassBasedToolsRequest):
    # ① Validate query and run stateful class-based inventory tools agent
    if not req.query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")
    try:
        return ClassBasedToolsResponse(**run_class_based_tools_agent(req.query))
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
