⚖️ The Refund Bench#

⚖️ The Refund Bench implements a 4-stage agentic food dispute adjudication pipeline that isolates verifiable claims, runs independent multi-model voting benches (OpenAI, Gemini, Groq), and computes code-driven refunds with auto-approval safety caps.

Unit 1

How It Works#

The dispute pipeline design, sensor evidence isolation, multi-model voting, and code pricing.

1

Concept#

In consumer apps, dispute resolution fails when an LLM is directly asked to "read the customer complaint and decide what refund to offer". Single-turn prompts suffer from three catastrophic failure modes:

  1. Sycophantic capitulation: If an angry customer demands "refund everything immediately", an unconstrained LLM complies, ignoring order history.
  2. Arithmetic hallucination: LLMs struggle with reliable price deductions, taxes, and delivery fees, frequently inventing arbitrary amounts.
  3. Single-model bias: Individual models have idiosyncratic tolerances for late deliveries vs packaging damage.

The Refund Bench solves this with a strict 4-stage pipeline separation of concerns:

  1. Stage 1 (Evidence Snapshot): Freezes physical sensors (timeline timestamps, pickup weights, door rating, packaging sensor) into an immutable JSON context.
  2. Stage 2 (Grievance Extraction): Breaks free-text complaints into atomic, checkable assertions with co-reference resolution ("two of four" → "2 of 4 Hyderabadi Chicken Biryani units").
  3. Stage 3 (Multi-Judge Bench): Multiple independent models (OpenAI, Gemini, Groq) adjudicate each grievance in parallel into UPHELD, REJECTED, or ESCALATE. Code calculates majority vote.
  4. Stage 4 (Settlement & Settle): Python code (not the LLM) calculates approved and held amounts, enforces the auto-approval cap, and prompts a support writer to compose the customer communication.
2

Theory & Concepts#

Core Principles

  1. Strict Evidence-Bound Adjudication: If physical evidence (e.g. packaging condition or partner behavior) is silent or missing, judges MUST return ESCALATE rather than guessing or rejecting.
  2. Cross-Provider Ensemble: Using diverse model families (GPT, Gemini, Llama/Groq) eliminates single-provider systematic bias and temperature variance.
  3. Deterministic Financial Calculations: Financial transactions and ledger entries are executed entirely in deterministic Python code based on line-item catalogs and frozen fees, preventing hallucinated amounts.
  4. Auto-Approval Guardrail Caps: Any claim exceeding the threshold (e.g. ₹2,000) automatically shifts approved refunds into held status for human supervisor review.

main.py#

FastAPI route handler for POST /api/refund-bench in server/main.py.

@app.post("/api/refund-bench", response_model=RefundBenchResponse)
def refund_bench_service(req: RefundBenchRequest):
    # ① Execute 4-stage multi-judge food dispute adjudication pipeline
    try:
        return RefundBenchResponse(
            **run_refund_bench(req.complaint_text, req.bench, req.cap)
        )
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
