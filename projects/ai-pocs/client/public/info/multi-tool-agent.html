How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

Multi-Tool Agent scales the LangChain agent up from one tool to a toolkit of four distinct capabilities: get_weather(city), add(a, b), multiply(a, b), and get_population(city). With multiple tools on the table, the LLM must act as a semantic router and planner — deciding not just whether to use a tool, but which combination of tools satisfies a compound user request.

When asked a multi-part question such as "What's the weather in Tokyo, and what is 12 times 12?", the agent dispatches both get_weather(city="Tokyo") and multiply(a=12, b=12), collects both tool outputs, and synthesizes a single coherent answer. Conversely, if asked "Who wrote Romeo and Juliet?", it recognizes that none of the four tools apply and answers directly.

2

Theory & Concepts#

1. Semantic Tool Selection Across a Toolkit

When multiple tools are registered in tools=[get_weather, add, multiply, get_population], every LLM request includes the JSON Schema definitions for all four functions. The model compares the user's intent against each tool's name, parameter types, and docstring to pick the right match without any hardcoded if/elif routing logic in Python.

2. Parallel Multi-Tool Calls in a Single Turn

Modern tool-calling models can emit multiple items in a single tool_calls array when sub-questions are independent (for example, looking up Tokyo's weather and multiplying two numbers at the same time). LangChain executes all requested tools, appends a ToolMessage for each one, and feeds the combined observations back to the model in the next step.

3. Atomic, Single-Purpose Tool Design

Notice that add(a, b) and multiply(a, b) are separate, narrowly typed functions rather than one vague do_stuff(query: str) function. Narrow, well-named tools with unambiguous parameter signatures dramatically reduce argument-extraction errors and can be composed freely by the agent.

4. Guarding Against Lazy Tool Summaries in the System Prompt

Smaller or faster models sometimes see a tool output in the conversation history and reply vaguely (e.g., "I have fetched the weather and calculation for you above"), forgetting that the end user cannot see raw ToolMessage blocks. The system prompt explicitly instructs: "Always state the final result clearly and completely in your answer."

"""
Langchain Version V1 - Agents (multiple tools + visible tool calls)

Teaching idea: give the agent SEVERAL tools, then SHOW what it does internally.
For each question the agent: reads the tools -> decides which to call ->
calls it -> reads the result -> writes a final answer. The step trace below
makes that loop visible so students can see the function calls happen.

NOTE on the OpenAI 429 ('insufficient_quota'): billing state, not a bug.
PROVIDER="groq" (free) keeps you teaching without OpenAI credits.
"""

import os

from dotenv import find_dotenv, load_dotenv
from langchain.agents import create_agent
from langchain_openai import ChatOpenAI
from pydantic import BaseModel

# ---------------------------------------------------------------------------
# Configuration & Provider Selection
# ---------------------------------------------------------------------------
# Load API keys and model names from .env
load_dotenv(find_dotenv())

# Pick a provider: "groq" (free + fast), "gemini" (free tier) or "openai" (needs billing).
# Its settings are read from <PROVIDER>_MODEL / <PROVIDER>_API_KEY / <PROVIDER>_BASE_URL in .env
# (get keys at https://console.groq.com or https://aistudio.google.com)
PROVIDER = "groq"
prefix = PROVIDER.upper()


# ---------------------------------------------------------------------------
# Request & Response Schemas (Pydantic)
# ---------------------------------------------------------------------------
class MultiToolAgentRequest(BaseModel):
    """Input payload for multi-tool LangChain agent queries."""

    message: str = "What's the weather in Tokyo, and what is 12 times 12?"


class MultiToolAgentResponse(BaseModel):
    """Output payload containing the final response and tool call indicator."""

    message: str
    response: str
    tool_called: bool


# ---------------------------------------------------------------------------
# Tools
#   1. Type hints (city: str)  -> tell the model what arguments to pass
#   2. The docstring           -> tells the model WHEN to use this tool
# ---------------------------------------------------------------------------
def get_weather(city: str) -> str:
    """Get the current weather for a given city."""
    return f"The weather in {city} is sunny, 28 degrees C."


def add(a: float, b: float) -> float:
    """Add two numbers together."""
    return a + b


def multiply(a: float, b: float) -> float:
    """Multiply two numbers together."""
    return a * b


def get_population(city: str) -> str:
    """Get the approximate population of a major city."""
    data = {
        "new york": "8.5 million",
        "london": "9 million",
        "bangalore": "13 million",
        "tokyo": "14 million",
    }
    return data.get(city.lower(), f"Sorry, I don't have population data for {city}.")


# ---------------------------------------------------------------------------
# Build the agent
# ---------------------------------------------------------------------------
# ① Initialize the LLM client pointed at the configured provider
#   (placeholder key avoids an import-time crash when the key is unset)
llm = ChatOpenAI(
    model=os.getenv(f"{prefix}_MODEL"),
    api_key=os.getenv(f"{prefix}_API_KEY") or "missing-key",
    base_url=os.getenv(f"{prefix}_BASE_URL") or None,
    temperature=0,
    timeout=20.0,
)

# ② Create the multi-tool LangChain agent with all 4 tools registered
agent = create_agent(
    model=llm,
    tools=[get_weather, add, multiply, get_population],
    # Tighter prompt: force the model to actually state the result so we don't
    # get vague answers like "that's the current weather".
    system_prompt=(
        "You are a helpful assistant. Use the available tools when needed. "
        "Always state the final result clearly and completely in your answer."
    ),
)


# ---------------------------------------------------------------------------
# Core Service Logic
# ---------------------------------------------------------------------------
def run_multi_tool_agent(question: str = "What's the weather in Tokyo, and what is 12 times 12?") -> tuple[str, bool]:
    """Run a user question through the multi-tool LangChain agent."""
    # ③ Invoke the multi-tool agent with the user's question
    messages = agent.invoke({"messages": [{"role": "user", "content": question}]})["messages"]

    # ④ Detect whether one or more tools were executed during the turn
    tool_called = any(m.type == "tool" for m in messages)

    # ⑤ The last message is the final synthesized answer
    return messages[-1].content, tool_called

server/main.py

FastAPI route handler for POST /api/multi-tool-agent (multi_tool_agent_service) in server/main.py.

from dotenv import find_dotenv, load_dotenv
from fastapi import FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware

from services import (
    MultiToolAgentRequest,
    MultiToolAgentResponse,
    run_multi_tool_agent,
)

# Load environment variables
load_dotenv(find_dotenv())

app = FastAPI(title="AI POCs API")

# Enable CORS for frontend requests
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)


@app.post("/api/multi-tool-agent", response_model=MultiToolAgentResponse)
def multi_tool_agent_service(req: MultiToolAgentRequest):
    # ① Validate message and invoke LangChain multi-tool agent
    if not req.message.strip():
        raise HTTPException(status_code=400, detail="Message cannot be empty")
    try:
        reply, tool_called = run_multi_tool_agent(req.message)
        return MultiToolAgentResponse(message=req.message, response=reply, tool_called=tool_called)
    except Exception as exc:
        raise HTTPException(status_code=500, detail=str(exc))
