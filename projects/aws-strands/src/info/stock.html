🗄️ Inventory Manager

class-based stateful tools via Strands + Bedrock

Concept

Grouping related tools inside a Python class lets them share a single stateful resource — a shared self.products store — instead of each function maintaining isolated state. A module-level instance preserves this state across requests so updates made in one turn are immediately visible in the next.

Theory & Concepts

The Inventory Manager demo explores shared state and multi-turn persistence in tool-calling agents:

  • Class-Based Stateful Tools: Tools defined as methods on InventoryTools share access to self.products. When the agent calls update_stock, the modified count is instantly visible to subsequent calls to check_stock within the same turn.
  • Module-Level Persistence: By keeping the _inventory instance at module level in stock_agent.py, stock updates persist across separate HTTP requests from the browser without requiring immediate database re-fetching.
  • Atomic Verification: The agent can update an item's stock and immediately verify the new count before responding, ensuring reliable verification in automated inventory tasks.

"""Module 2 demo — class-based tools (the shared-resource pattern).

Grouping related tools in a class lets them share ONE resource (here, a single
``self.products`` store) instead of each tool opening its own. A module-level
instance keeps the state alive across requests, so an update made in one call
is visible to the next — check, update, then re-check and watch it persist.
"""

# Import Agent runner and @tool decorator from Strands
from strands import Agent, tool
from strands.models.bedrock import BedrockModel

from config import MODEL_ID, agent_text


class InventoryTools:
    """Class encapsulating shared, mutable inventory state across tool methods."""

    def __init__(self):
        # Shared resource: all tools access the same data store.
        # In production: self.db = connect_to_database()   <-- opened ONCE
        self.products = {
            "PROD-123": {"name": "Wireless Mouse", "quantity": 15, "price": 29.99},
            "PROD-456": {"name": "USB-C Hub", "quantity": 0, "price": 49.99},
            "PROD-789": {"name": "Mechanical Keyboard", "quantity": 8, "price": 89.99},
        }

    @tool
    def check_stock(self, product_id: str) -> str:
        """Check product stock level.

        Args:
            product_id: The product ID to check
        """
        # Step 1: Look up product entry in shared state
        product = self.products.get(product_id)
        if not product:
            return f"Product {product_id} not found"
        # Step 2: Return current stock quantity and unit price
        return f"{product['name']}: {product['quantity']} units at ${product['price']}"

    @tool
    def update_stock(self, product_id: str, quantity: int) -> str:
        """Update product stock quantity.

        Args:
            product_id: The product ID to update
            quantity: New quantity to set
        """
        # Step 1: Update in-memory quantity if valid product ID
        if product_id in self.products:
            self.products[product_id]["quantity"] = quantity
            return f"Updated {product_id} to {quantity} units"
        return f"Product {product_id} not found"


# One shared singleton instance — state persists across successive HTTP requests.
_inventory = InventoryTools()


def manage(question: str) -> str:
    """Answer a stock request with the class-based, stateful inventory tools."""
    # Step 1: Provide bound methods (_inventory.check_stock, _inventory.update_stock)
    # directly to the agent. Strands inspects the bound methods and their parent instance.
    agent = Agent(
        model=BedrockModel(model_id=MODEL_ID),
        tools=[_inventory.check_stock, _inventory.update_stock],
        callback_handler=None,
    )

    # Step 2: Execute ReAct loop; modifications made by update_stock remain in memory
    return agent_text(agent(question))
