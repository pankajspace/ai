How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

LangGraph ReAct Agent sits right beside the Strands Hello World demo to prove a key architectural insight: the ReAct (Reason + Act) agent pattern is universal across AI frameworks. Here, the same Amazon Bedrock model (amazon.nova-lite-v1:0) is driven by LangGraph's create_react_agent() instead of AWS Strands.

Equipped with a simple @tool def greet(name: str) -> str tool, the agent is asked to "Greet Alice and Bob". It reasons that two greetings are needed, invokes greet("Alice") and greet("Bob"), observes the friendly outputs, and synthesizes a final response while the service extracts all intermediate tool messages from the graph state for display in the UI.

2

Theory#

1. The ReAct Loop (Reason → Act → Observe)

Whether implemented in LangGraph, AWS Strands, or raw OpenAI code, a ReAct agent executes the same cyclic state graph:

  1. Reason (Agent Node): The LLM inspects the conversation state and decides whether it needs external tool actions or can answer immediately.
  2. Act (Tools Node): If the LLM emits tool_calls, the graph routes to the tool executor node, which runs greet(name) for each call.
  3. Observe (State Edge): Each tool output is appended to the state's messages list as a ToolMessage, and control loops back to the Agent Node.

2. Side-by-Side Framework Comparison: Strands vs. LangGraph

  • Model Setup: Strands uses BedrockModel(model_id=...); LangChain/LangGraph uses init_chat_model(model_id, model_provider="bedrock_converse").
  • Tool Decorator: Strands uses from strands import tool; LangGraph uses from langchain_core.tools import tool.
  • Invocation: Strands calls agent(prompt); LangGraph calls agent.invoke({"messages": [("user", prompt)]}).

3. Extracting Tool Outputs from Graph State

LangGraph returns the complete state dictionary {"messages": [...]}. Filtering for getattr(m, "type", None) == "tool" isolates the exact strings returned by greet(), while messages[-1].content holds the assistant's final reply.

Code explanation#

1. Purpose of Each File in This Demo

  • src/python/02_hello_world_langgraph.py: Implements a tool-calling ReAct agent using LangChain and LangGraph backed by Amazon Bedrock's Converse API. It defines the @tool greet(name) function, constructs the state graph via create_react_agent(), and exposes run_langgraph_agent(prompt).
  • src/python/app.py: Dynamically imports 02_hello_world_langgraph.py as s_langgraph at startup and exposes the POST /api/langgraph-agent endpoint via langgraph_route().
  • src/index.html + src/js/main.js: Sends the user's prompt (e.g., "Please greet Alice and Bob.") to POST /api/langgraph-agent and renders both the assistant's final answer and the list of observed tool messages.

2. Classes, Tools, Graph Setup, and Functions in 02_hello_world_langgraph.py

  • Step ① Environment Loading (load_dotenv(find_dotenv())): Loads AWS credentials and region settings from .env so LangChain's Bedrock provider can authenticate via boto3.
  • LangGraphAgentRequest(BaseModel) & LangGraphAgentResponse(BaseModel): Pydantic models documenting the input payload (prompt: str = "Please greet Alice and Bob.") and the output payload (prompt: str, response: str, and tool_calls: list[str]).
  • Step ② Model Identifier (model_id): Reads BEDROCK_MODEL_ID from the environment, defaulting to "amazon.nova-lite-v1:0".
  • @tool def greet(name: str) -> str: Decorated with LangChain's @tool decorator (from langchain.tools import tool). Accepts a person's name: str and returns f"Hello, {name}! Welcome to the world of AI agents.". Its docstring ("Greet someone by name.") and type annotation form the tool schema sent to Bedrock.
  • Step ③ Chat Model Initialization (llm = init_chat_model(model_id, model_provider="bedrock_converse")): Instantiates a LangChain chat model using the unified bedrock_converse provider, which translates LangChain messages and tool definitions into Amazon Bedrock Converse API calls.
  • Step ④ ReAct Graph Compilation (agent = create_react_agent(model=llm, tools=[greet])): Uses LangGraph's prebuilt factory to compile a cyclic state graph with an LLM reasoning node and a tool execution node. Unlike Strands' stateful Agent, a compiled LangGraph graph is stateless across invocations unless a checkpointer is attached, so each agent.invoke(...) call starts with a fresh message list.
  • run_langgraph_agent(prompt: str) -> dict: Executes the compiled graph and formats the result:
    • Step ⑤ (response = agent.invoke({"messages": [{"role": "user", "content": prompt}]})): Seeds the graph state with the user message and runs the Reason → Act → Observe cycle until the model emits a final response with no further tool calls. Extracts the full message history via messages = response["messages"].
    • Step ⑥ (tool_calls = [f"{m.name} -> {m.content}" for m in messages if m.type == "tool"]): Filters the conversation history for ToolMessage objects (m.type == "tool") to capture each tool execution and its returned greeting string, and returns {"prompt": prompt, "response": messages[-1].text, "tool_calls": tool_calls}.

3. Route Handler in app.py

  • langgraph_route() (POST /api/langgraph-agent):
    • Step ①: Parses the request JSON, extracts and strips prompt (or message), and returns HTTP 400 if empty.
    • Step ②: Invokes s_langgraph.run_langgraph_agent(prompt), sets res["result"] = res.get("response"), and returns the JSON payload (including tool_calls) to the client.

4. End-to-End Execution Walkthrough

  1. The browser sends POST /api/langgraph-agent with { "prompt": "Please greet Alice and Bob." }.
  2. langgraph_route() in app.py validates the prompt and calls s_langgraph.run_langgraph_agent(prompt).
  3. run_langgraph_agent() calls agent.invoke({"messages": [{"role": "user", "content": prompt}]}) on the compiled LangGraph ReAct graph.
  4. On Turn 1, the LangGraph agent node calls Amazon Bedrock via bedrock_converse. Nova Lite inspects the greet tool schema and emits tool calls for greet(name="Alice") and greet(name="Bob").
  5. LangGraph's tool node executes greet("Alice") and greet("Bob"), appends two ToolMessage objects (m.type == "tool") to state["messages"], and routes back to the agent node.
  6. On Turn 2, Bedrock reads the tool outputs and produces the final assistant message (messages[-1].text).
  7. run_langgraph_agent() collects the tool messages into tool_calls and returns the dictionary to app.py, which sends the JSON response back to the browser.

LangGraph ReAct Hello World Agent Service.

"""LangGraph ReAct Hello World Agent Service.

Demonstrates the LangGraph tool-calling ReAct agentic loop on Amazon Bedrock:
1. Defines a tool `greet(name: str)`.
2. Passes the prompt to a LangGraph ReAct agent backed by Bedrock Converse.
3. Observes tool execution steps (calling greet for each person).
4. Synthesizes the final response.
"""

import os

from dotenv import find_dotenv, load_dotenv
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langgraph.prebuilt import create_react_agent
from pydantic import BaseModel

# ① Load AWS credentials and Bedrock configuration from .env
load_dotenv(find_dotenv())


class LangGraphAgentRequest(BaseModel):
    """Input payload for LangGraph Hello World Agent."""

    prompt: str = "Please greet Alice and Bob."


class LangGraphAgentResponse(BaseModel):
    """Output payload from LangGraph Hello World Agent."""

    prompt: str
    response: str
    tool_calls: list[str]


# ② Resolve the target Bedrock model identifier
model_id = os.getenv("BEDROCK_MODEL_ID", "amazon.nova-lite-v1:0")


@tool
def greet(name: str) -> str:
    """Greet someone by name."""
    return f"Hello, {name}! Welcome to the world of AI agents."


# ③ Initialize the LLM via the Amazon Bedrock Converse provider
llm = init_chat_model(model_id, model_provider="bedrock_converse")

# ④ Create a LangGraph ReAct agent bound to the greet tool
agent = create_react_agent(model=llm, tools=[greet])


def run_langgraph_agent(prompt: str = "Please greet Alice and Bob.") -> dict:
    """Run the LangGraph tool-enabled ReAct agent."""
    # ⑤ Invoke the ReAct agent loop (Reason -> Act -> Observe)
    response = agent.invoke({"messages": [{"role": "user", "content": prompt}]})
    messages = response["messages"]

    # ⑥ Every "tool" message is the observation from one greet() call
    tool_calls = [f"{m.name} -> {m.content}" for m in messages if m.type == "tool"]

    return {"prompt": prompt, "response": messages[-1].text, "tool_calls": tool_calls}

def _load_service(filename: str, alias: str):
    # ① Resolve the numbered service file path and create its import spec
    file_path = _CUR_DIR / filename
    spec = importlib.util.spec_from_file_location(f"services.{alias}", file_path)
    if spec is None or spec.loader is None:
        raise ImportError(f"Cannot load module from {file_path}")
    # ② Register and execute the module so its functions can be called by routes
    mod = importlib.util.module_from_spec(spec)
    sys.modules[f"services.{alias}"] = mod
    spec.loader.exec_module(mod)
    return mod

@bp.before_request
def enforce_rate_limit():
    # ① Only rate-limit mutating POST requests
    if request.method == "POST":
        # ② Check whether this client has exceeded 30 requests per hour
        blocked, msg, retry_after = check_rate_limit(
            request, max_requests=30, window_seconds=3600
        )
        if blocked:
            # ③ Return HTTP 429 with Retry-After header when rate-limited
            resp = jsonify({"error": msg})
            resp.status_code = 429
            resp.headers["Retry-After"] = str(retry_after)
            return resp

Quick revision#

Review these core concepts comparing LangGraph's ReAct agent architecture with AWS Strands on Amazon Bedrock:

  1. Framework-Agnostic ReAct Loop: The Reason → Act → Observe cycle is a fundamental AI agent pattern, not a library-specific feature; both LangGraph and AWS Strands drive the exact same Bedrock Converse tool-calling protocol underneath.
  2. LangChain's Unified Model Loader (init_chat_model): Calling init_chat_model(model_id, model_provider="bedrock_converse") connects LangChain/LangGraph to Amazon Bedrock's Converse API using the same amazon.nova-lite-v1:0 model ID as Strands.
  3. Prebuilt ReAct State Graph (create_react_agent): langgraph.prebuilt.create_react_agent(model=llm, tools=[greet]) compiles a cyclic state graph containing an agent node (LLM call), a conditional router (checking for tool_calls), and a tool execution node.
  4. Tool Definition Parity (@tool): Just like Strands, LangChain's @tool decorator inspects the Python function name (greet), parameter type hints (name: str), and docstring ("Greet someone by name.") to generate the JSON Schema sent to the model.
  5. Multi-Entity Tool Fan-Out: When prompted with "Please greet Alice and Bob", the model recognizes two target entities and invokes greet("Alice") and greet("Bob") before synthesizing its final reply.
  6. Stateless Compiled Graph Invocation: Because create_react_agent is compiled without a persistent checkpointer here, agent can be instantiated once at module level and safely invoked concurrently via agent.invoke({"messages": [...]}).
  7. Observing Tool Execution via ToolMessage: In LangGraph, every tool return value is appended to response["messages"] as a message with m.type == "tool", allowing [f"{m.name} -> {m.content}" for m in messages if m.type == "tool"] to capture the full execution trace.
  8. Boilerplate Comparison (LangGraph vs. Strands): While LangGraph offers fine-grained graph node and edge customization for complex state machines, AWS Strands reduces standard tool-calling agents to a more concise Agent(model=..., tools=[...])(prompt) call.
