How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

Tip Calculator Agent illustrates two core principles of reliable tool design: semantic parameter extraction from free-form language and offloading exact arithmetic to deterministic code.

Whether a user writes "The bill is $85, 20% tip, split 4 ways", "Dinner was 120 dollars for 3 of us with an 18 percent tip", or simply "Tip on $50", the Bedrock agent maps those varied phrasings into a single typed call to calculate_tip(bill_amount: float, tip_percent: float = 15.0, num_people: int = 1). Python performs the exact floating-point math and returns a structured dictionary of rounded dollar amounts that the agent summarizes in natural prose.

2

Theory#

1. Intent and Entity Extraction Without Regex

Before LLMs, parsing a sentence like "We split an $85.50 tab four ways after adding twenty percent" required brittle regular expressions and number-word parsers. With tool calling, the LLM acts as a universal semantic parser that extracts entities, converts them to typed numbers (bill_amount=85.5, tip_percent=20.0, num_people=4), and invokes the tool.

2. Optional Parameters via Python Default Values

When Strands introspects def calculate_tip(bill_amount: float, tip_percent: float = 15.0, num_people: int = 1), only bill_amount is marked as required in the generated JSON Schema. If the user says "What's the tip on a $64 bill?" without specifying a percentage or party size, the tool safely falls back to a 15% tip for 1 person.

3. Division of Labor: Language vs. Arithmetic

LLMs predict tokens probabilistically and regularly make rounding or division mistakes on non-trivial numbers (e.g., $137.45 × 1.18 / 7). Offloading the calculation to Python guarantees cent-level accuracy (round(total / num_people, 2)) while keeping the user interface conversational.

4. Structured Dict Return Values

Returning a self-describing dictionary ({"bill": ..., "tip_percent": ..., "tip_amount": ..., "total": ..., "per_person": ...}) gives the model labelled fields to read on the observation step, preventing it from confusing the total bill with the per-person share.

1. Core AI & Tool Components in 04_tip_calculator.py

  • Pydantic Contracts (TipCalculatorRequest & TipCalculatorResponse): Define the input query: str and output dictionary fields (query: str, response: str, tool_calls: list[str]).
  • Step ② Model Identifier (model_id): Resolves the target Bedrock model ID, defaulting to "amazon.nova-lite-v1:0".
  • @tool def calculate_tip(bill_amount: float, tip_percentage: float, num_people: int = 1) -> dict:
    • Parameters & Schema Generation: Strands inspects the three typed parameters. Because bill_amount: float and tip_percentage: float have no default values, they are marked required in the Bedrock JSON Schema, while num_people: int = 1 is marked optional with a default of 1.
    • Deterministic Math: Computes tip = bill_amount * (tip_percentage / 100), total = bill_amount + tip, and per_person = total / num_people.
    • Return Value: Returns a dictionary with rounded cent values: {"bill": bill_amount, "tip": round(tip, 2), "total": round(total, 2), "per_person": round(per_person, 2)}.
  • run_tip_calculator_agent(query: str) -> dict:
    • Step ③: Instantiates Agent(model=BedrockModel(model_id=model_id), tools=[calculate_tip]).
    • Step ④: Calls response = agent(query) so the LLM extracts the numeric parameters from plain English and executes calculate_tip.
    • Step ⑤: Extracts every "toolUse" block from agent.messages into tool_calls and returns {"query": query, "response": str(response), "tool_calls": tool_calls}.

2. End-to-End AI Execution Walkthrough

  1. run_tip_calculator_agent(query) creates a fresh Strands Agent bound to calculate_tip and calls agent(query) (e.g., for "The bill is $85. What's a 20% tip, and how much does each person pay if we're splitting it 4 ways?").
  2. On Turn 1, Bedrock Nova Lite parses the natural-language query and emits a toolUse block: calculate_tip({"bill_amount": 85.0, "tip_percentage": 20.0, "num_people": 4}).
  3. Strands invokes calculate_tip(85.0, 20.0, 4) locally in Python, which returns {"bill": 85.0, "tip": 17.0, "total": 102.0, "per_person": 25.5} as a toolResult block.
  4. On Turn 2, Bedrock formats those exact numbers into a friendly breakdown ($17.00 tip, $102.00 total, $25.50 per person).
  5. Step ⑤ records the tool call in tool_calls and returns {"query": query, "response": str(response), "tool_calls": tool_calls}.

Tip Calculator Agent Service.

"""Tip Calculator Agent Service.

Demonstrates intent-driven tool invocation over keyword matching:
1. Agent understands natural language intent regardless of phrasing.
2. Extracts numeric parameters: bill amount, tip percentage, and number of people.
3. Invokes `calculate_tip(bill_amount, tip_percentage, num_people)`.
4. Returns computed totals and split amounts.
"""

import os

from dotenv import find_dotenv, load_dotenv
from pydantic import BaseModel
from strands import Agent, tool
from strands.models.bedrock import BedrockModel

# ① Load AWS credentials and Bedrock configuration from .env
load_dotenv(find_dotenv())


class TipCalculatorRequest(BaseModel):
    """Input payload for Tip Calculator Agent."""

    query: str = "The bill is $85. What's a 20% tip, and how much does each person pay if we're splitting it 4 ways?"


class TipCalculatorResponse(BaseModel):
    """Output payload from Tip Calculator Agent."""

    query: str
    response: str
    tool_calls: list[str]


# ② Resolve the target Bedrock model identifier
model_id = os.getenv("BEDROCK_MODEL_ID", "amazon.nova-lite-v1:0")


@tool
def calculate_tip(bill_amount: float, tip_percentage: float, num_people: int = 1) -> dict:
    """Calculate tip and split the bill among people.

    Args:
        bill_amount: Total bill amount in dollars
        tip_percentage: Tip percentage (e.g., 15, 18, 20)
        num_people: Number of people splitting the bill (default: 1)
    """
    # Compute the tip amount, combined total, and per-person share
    tip = bill_amount * (tip_percentage / 100)
    total = bill_amount + tip
    per_person = total / num_people

    # Return a dictionary with rounded monetary values
    return {
        "bill": bill_amount,
        "tip": round(tip, 2),
        "total": round(total, 2),
        "per_person": round(per_person, 2),
    }


def run_tip_calculator_agent(
    query: str = "The bill is $85. What's a 20% tip, and how much does each person pay if we're splitting it 4 ways?",
) -> dict:
    """Run the Tip Calculator Agent."""
    # ③ Initialize the Strands Agent with BedrockModel and the calculate_tip tool
    agent = Agent(model=BedrockModel(model_id=model_id), tools=[calculate_tip])

    # ④ The agent extracts bill, tip % and group size from plain English and calls the tool
    response = agent(query)

    # ⑤ Collect every tool call (toolUse) from the message history
    tool_calls = [
        f"{block['toolUse']['name']}({block['toolUse']['input']})"
        for message in agent.messages
        for block in message["content"]
        if "toolUse" in block
    ]

    return {"query": query, "response": str(response), "tool_calls": tool_calls}

def _load_service(filename: str, alias: str):
    # ① Resolve the numbered service file path and create its import spec
    file_path = _CUR_DIR / filename
    spec = importlib.util.spec_from_file_location(f"services.{alias}", file_path)
    if spec is None or spec.loader is None:
        raise ImportError(f"Cannot load module from {file_path}")
    # ② Register and execute the module so its functions can be called by routes
    mod = importlib.util.module_from_spec(spec)
    sys.modules[f"services.{alias}"] = mod
    spec.loader.exec_module(mod)
    return mod

@bp.before_request
def enforce_rate_limit():
    # ① Only rate-limit mutating POST requests
    if request.method == "POST":
        # ② Check whether this client has exceeded 30 requests per hour
        blocked, msg, retry_after = check_rate_limit(
            request, max_requests=30, window_seconds=3600
        )
        if blocked:
            # ③ Return HTTP 429 with Retry-After header when rate-limited
            resp = jsonify({"error": msg})
            resp.status_code = 429
            resp.headers["Retry-After"] = str(retry_after)
            return resp

Quick revision#

Use these takeaways to review multi-parameter extraction and deterministic computation in Strands tools:

  1. Semantic Entity Extraction Over Regex: The LLM translates varied natural-language phrasings ("splitting it 4 ways", "for 3 of us", "20% tip") into typed numerical arguments without brittle regular expressions.
  2. Required vs. Optional Schema Fields: In calculate_tip(bill_amount: float, tip_percentage: float, num_people: int = 1), parameters without default values become required in the Bedrock JSON Schema, while num_people: int = 1 is optional.
  3. Deterministic Arithmetic in Python: Language models predict tokens probabilistically and can miscalculate decimals; delegating floating-point math and round(..., 2) to Python guarantees cent-level accuracy.
  4. Self-Describing Dictionary Returns: Returning {"bill": ..., "tip": ..., "total": ..., "per_person": ...} labels every computed number so the LLM never confuses the total bill with the per-person split.
  5. Google-Style Args: Docstring Parsing: Strands extracts each parameter's description from the Args: block and embeds it into the JSON Schema property description sent to Bedrock.
  6. Single-Round-Trip Tool Execution: Because all three parameters can be extracted from the initial prompt at once, the agent completes the tool call in a single Reason → Act → Observe cycle.
  7. Auditing Extracted Arguments: Inspecting block['toolUse']['input'] inside agent.messages lets you verify the exact numeric values the model parsed from the user's sentence.
