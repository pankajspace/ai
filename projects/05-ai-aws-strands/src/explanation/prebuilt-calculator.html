🧮 Math Assistant#

Unit 1

How It Works#

The idea behind the demo, the request it sends and the function calls that answer it.

1

Concept#

Prebuilt Calculator Agent introduces the strands_tools ecosystem — a library of battle-tested, off-the-shelf tools maintained alongside the AWS Strands SDK. By simply writing from strands_tools import calculator and passing tools=[calculator] to Agent(), the agent gains a full symbolic and numerical mathematics engine powered by SymPy without writing a single line of custom tool code.

Paired with a focused system_prompt="You are a helpful math assistant.", the agent recognizes mathematical expressions, delegates evaluation to the prebuilt calculator tool, and explains the exact result.

2

Theory#

1. Why LLMs Struggle with Multi-Digit Math

Transformer language models tokenize numbers into subword chunks and predict the next token via matrix multiplications and softmax probabilities — they do not run an arithmetic logic unit (ALU). While an LLM can memorize 12 × 12 = 144, asking it for 429 or the derivative of sin(x2) · ex by pure token prediction frequently produces plausible-looking wrong digits.

2. Symbolic & Numerical Capabilities of strands_tools.calculator

Unlike a basic four-function eval() wrapper, the prebuilt calculator tool supports multiple modes via SymPy:

  • Evaluate: Exact arithmetic, powers, roots, and trigonometry.
  • Solve: Algebraic equations and systems of equations.
  • Calculus: Symbolic differentiation (derive) and integration (integrate).
  • Matrix Operations: Determinants, inverses, and eigenvalues.

3. Standing Instructions via system_prompt

Passing system_prompt="You are a helpful math assistant." when constructing the Agent attaches a persistent system instruction to every Bedrock Converse call in the loop, priming the model to reach for its mathematical toolset and format explanations clearly.

Code explanation#

1. Purpose of Each File

  • src/python/07_prebuilt_tools.py — Defines the Prebuilt Calculator Agent service: imports the off-the-shelf calculator tool from strands_tools, configures the Agent with a standing math-assistant system prompt, runs the user's mathematical query, and extracts every tool call from agent.messages.
  • src/python/app.py — Loads 07_prebuilt_tools.py dynamically as s_calc via _load_service(), enforces rate limiting (30 POSTs/hour), and exposes POST /api/prebuilt-calculator via prebuilt_calculator_route().
  • src/index.html + src/js/main.js — Renders the 🧮 Math Assistant interactive demo card, reads the mathematical expression or word problem from the input box, sends POST /api/prebuilt-calculator with { query }, and displays both the natural-language answer and the exact calculator(...) invocation.

2. Pydantic Schemas, Prebuilt Tool & Agent Setup in 07_prebuilt_tools.py

  • Step ① — Environment Configuration (load_dotenv(find_dotenv())): Loads AWS credentials and optional Bedrock configuration from the nearest .env file into environment variables.
  • PrebuiltCalculatorRequest(BaseModel) & PrebuiltCalculatorResponse(BaseModel): Document the expected input payload (query: str defaulting to "What's 42 raised to the power of 9?") and the structured output dictionary (query, response, and tool_calls: list[str]).
  • Step ② — Model Selection (model_id): Reads BEDROCK_MODEL_ID from the environment, defaulting to "amazon.nova-lite-v1:0".
  • Prebuilt Tool (from strands_tools import calculator): Imports the SymPy-backed calculator tool directly from the strands_tools package — providing symbolic and numerical expression evaluation, equation solving, differentiation, integration, and matrix operations with zero custom @tool code.
  • Service Entry Point — run_prebuilt_calculator_agent(query: str) -> dict:
    • Step ③: Instantiates Agent(model=BedrockModel(model_id=model_id), tools=[calculator], system_prompt="You are a helpful math assistant.") so the standing system instruction primes Bedrock to delegate arithmetic and symbolic math to calculator.
    • Step ④: Calls response = agent(query), triggering the Strands tool-use loop where Bedrock emits a toolUse block for calculator, Strands evaluates the expression via SymPy, and returns the exact result in a toolResult block.
    • Step ⑤: Iterates over agent.messages and formats every "toolUse" block as f"{block['toolUse']['name']}({block['toolUse']['input']})" into tool_calls, returning {"query": query, "response": str(response), "tool_calls": tool_calls}.

3. Flask Route Handler in src/python/app.py

  • prebuilt_calculator_route() (POST /api/prebuilt-calculator):
    • Step ①: Parses the JSON request body with request.get_json(force=True, silent=True), extracts query (or fallback message), and returns HTTP 400 if empty.
    • Step ②: Calls s_calc.run_prebuilt_calculator_agent(query), copies res["response"] into res["result"] for the unified frontend renderer, and returns the JSON payload (or HTTP 500 if an exception occurs).

4. End-to-End Walkthrough: How All Entities Connect

  1. The user clicks Run on the 🧮 Math Assistant card in src/index.html; src/js/main.js sends POST /api/prebuilt-calculator with {"query": "What's 42 raised to the power of 9?"}.
  2. Flask's @bp.before_request hook (enforce_rate_limit()) verifies the client is within the 30-requests/hour quota and forwards the request to prebuilt_calculator_route().
  3. prebuilt_calculator_route() validates the non-empty query and calls s_calc.run_prebuilt_calculator_agent(query) in 07_prebuilt_tools.py.
  4. run_prebuilt_calculator_agent() creates a BedrockModel and a Strands Agent configured with tools=[calculator] and system_prompt="You are a helpful math assistant.".
  5. Calling agent(query) sends the user prompt, the system prompt, and the calculator JSON Schema to Amazon Bedrock (amazon.nova-lite-v1:0) via the Converse API.
  6. Bedrock responds with stopReason="tool_use" and a toolUse block specifying name="calculator" and input {"expression": "42**9"} (or equivalent).
  7. The Strands runtime invokes strands_tools.calculator locally, which uses SymPy to compute 406,671,383,849,472 with arbitrary-precision integer arithmetic and sends it back to Bedrock inside a toolResult message.
  8. Bedrock generates the final natural-language answer, run_prebuilt_calculator_agent() extracts the tool_calls trace from agent.messages, and app.py returns the JSON response to the browser card.

src/python/07_prebuilt_tools.py

Pre-built Calculator Tool Agent Service.

"""Pre-built Calculator Tool Agent Service.

Demonstrates integrating pre-built community tools with system prompts:
1. Standing System Prompt: "You are a helpful math assistant."
2. Prebuilt `calculator` tool from the `strands_tools` package (no tool code to write).
3. Evaluates complex mathematical queries with precise computation.
"""

import os

from dotenv import find_dotenv, load_dotenv
from pydantic import BaseModel
from strands import Agent
from strands.models.bedrock import BedrockModel
from strands_tools import calculator

# ① Load AWS credentials and Bedrock configuration from .env
load_dotenv(find_dotenv())


class PrebuiltCalculatorRequest(BaseModel):
    """Input payload for Prebuilt Calculator Agent."""

    query: str = "What's 42 raised to the power of 9?"


class PrebuiltCalculatorResponse(BaseModel):
    """Output payload from Prebuilt Calculator Agent."""

    query: str
    response: str
    tool_calls: list[str]


# ② Resolve the target Bedrock model identifier
model_id = os.getenv("BEDROCK_MODEL_ID", "amazon.nova-lite-v1:0")


def run_prebuilt_calculator_agent(query: str = "What's 42 raised to the power of 9?") -> dict:
    """Run the Prebuilt Calculator Agent."""
    # ③ Initialize the Strands Agent with the prebuilt calculator tool and a standing system prompt
    agent = Agent(
        model=BedrockModel(model_id=model_id),
        tools=[calculator],
        system_prompt="You are a helpful math assistant.",
    )

    # ④ Execute the math query
    response = agent(query)

    # ⑤ Collect every tool call the agent made from its message history
    tool_calls = [
        f"{block['toolUse']['name']}({block['toolUse']['input']})"
        for message in agent.messages
        for block in message["content"]
        if "toolUse" in block
    ]

    return {"query": query, "response": str(response), "tool_calls": tool_calls}

def _load_service(filename: str, alias: str):
    # ① Resolve the numbered service file path and create its import spec
    file_path = _CUR_DIR / filename
    spec = importlib.util.spec_from_file_location(f"services.{alias}", file_path)
    if spec is None or spec.loader is None:
        raise ImportError(f"Cannot load module from {file_path}")
    # ② Register and execute the module so its functions can be called by routes
    mod = importlib.util.module_from_spec(spec)
    sys.modules[f"services.{alias}"] = mod
    spec.loader.exec_module(mod)
    return mod

@bp.before_request
def enforce_rate_limit():
    # ① Only rate-limit mutating POST requests
    if request.method == "POST":
        # ② Check whether this client has exceeded 30 requests per hour
        blocked, msg, retry_after = check_rate_limit(
            request, max_requests=30, window_seconds=3600
        )
        if blocked:
            # ③ Return HTTP 429 with Retry-After header when rate-limited
            resp = jsonify({"error": msg})
            resp.status_code = 429
            resp.headers["Retry-After"] = str(retry_after)
            return resp

@bp.route("/api/hello-world-agent", methods=["POST"])
def hello_world_route():
    # ① Parse prompt from JSON payload and reject empty values
    data = request.get_json(force=True, silent=True) or {}
    prompt = (data.get("prompt") or data.get("message") or "").strip()
    if not prompt:
        return jsonify({"error": "Prompt cannot be empty"}), 400

        # ② Invoke the Strands Hello World Agent in 01_hello_world_agent.py

Quick revision#

Use this numbered checklist to review the core concepts, Strands primitives, and engineering choices in the 🧮 Math Assistant demo:

  1. Why LLMs Need a Calculator Tool: Autoregressive language models predict subword tokens probabilistically rather than executing hardware ALU instructions, making multi-digit exponentiation (like 429) or symbolic calculus prone to hallucinated digits without an external math engine.
  2. Zero-Boilerplate Prebuilt Tools (strands_tools): Importing from strands_tools import calculator and passing tools=[calculator] gives an agent production-tested mathematical capabilities without writing a single custom @tool function or docstring schema.
  3. SymPy Symbolic & Numerical Engine: Under the hood, strands_tools.calculator uses SymPy to support exact arithmetic evaluation, algebraic equation solving, symbolic derivatives and integrals, and matrix operations.
  4. Standing Instructions via system_prompt: Passing system_prompt="You are a helpful math assistant." to Agent(...) attaches a persistent system prompt to every Bedrock Converse call, steering the model to use the calculator tool and explain mathematical results clearly.
  5. Automatic Tool Spec Registration: Even for prebuilt tools imported from external packages, Agent(tools=[calculator]) automatically attaches the tool's name, description, and input JSON Schema (expression, mode, etc.) to the Bedrock Converse request.
  6. Two-Turn Converse Loop: A single call to agent(query) transparently executes two Bedrock Converse round-trips: Turn 1 translates English into a formal calculator tool call, and Turn 2 formats the exact SymPy output into a human-friendly response.
  7. Inspecting agent.messages for Observability: Scanning message["content"] for "toolUse" blocks after agent(query) completes yields an exact audit log of the expressions passed to calculator.
  8. Arbitrary-Precision Accuracy: Because Python and SymPy support arbitrary-precision integers, evaluating 42**9 returns the exact 15-digit integer (406671383849472) without floating-point overflow or token-prediction drift.
  9. Dynamic Module Loading in app.py: Because Python filenames starting with digits (07_prebuilt_tools.py) cannot be imported with standard import syntax, app.py uses importlib.util.spec_from_file_location() in _load_service() to load each numbered demo cleanly.
