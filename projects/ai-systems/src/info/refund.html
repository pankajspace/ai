🏛️ The Refund Bench

4-Stage Agentic Dispute Resolution & Multi-Judge System (OpenAI · Gemini · Groq)

Concept

In consumer platforms like food delivery, ride hailing, and e-commerce, customer complaints are messy, emotional, and often conflate multiple independent issues into a single angry paragraph. Attempting to resolve disputes using a single monolithic LLM prompt fails due to hallucinated refund policies, arithmetic mistakes, vulnerability to prompt injection, and correlated errors.

The Refund Bench solves this with an industrial 4-stage agentic pipeline:

  • Stage 1 (Intake & Evidence Freeze): Freezes immutable transactional facts from the database (order items, GPS logs, restaurant handoff timestamps, delivery SLA) into an unalterable context envelope.
  • Stage 2 (Atomic Grievance Extraction): An intake LLM resolves pronouns (co-reference resolution) and breaks the complaint into atomic, verifiable claim units (e.g. g1: LATE_DELIVERY, g2: MISSING_ITEM) while discarding insults and demands.
  • Stage 3 (The Multi-Judge Bench): Evaluates each grievance across 3 distinct model families (OpenAI gpt-4o-mini, Google Gemini gemini-3.6-flash, and Groq gpt-oss-20b) using self-consistency voting with majority consensus calculated in code.
  • Stage 4 (Code Settlement & Guardrails): Deterministic Python code computes refund amounts based on actual line-item prices, enforces a hard ₹2,000 auto-approval ceiling, and synthesizes an empathetic customer email.

Theory & Concepts

Self-Consistency and Uncorrelated Error Distributions

This architecture leverages core distributed AI systems principles:

  • Why 3 Distinct Judge Models? Querying the same model three times (e.g. GPT-4o-mini thrice) risks correlated errors—systematic biases or blind spots shared by that specific training checkpoint. By seating OpenAI, Gemini, and Groq as the 3 judges, the system samples independent probability distributions. If Gemini misses a nuance, OpenAI and Groq provide the consensus majority.
  • Separation of Fact-Finding and Money Movement: LLMs are notorious for hallucinating arithmetic and calculating incorrect totals. In The Refund Bench, LLMs only output categorical verdicts (UPHELD, REJECTED, or ESCALATE). The actual rupee calculation is performed by pure deterministic Python code using ground-truth order item prices.
  • The Auto-Approve Cap (₹2,000 Financial Guardrail): Even if all 3 judges uphold every grievance, if the total refund exceeds the ₹2,000 policy threshold, the entire payout is automatically routed to human operations for supervisor sign-off, protecting the platform from catastrophic adversarial abuse.

Backend

Coordinates grievance extraction, 3-model judge bench, and deterministic settlement. 
def adjudicate_dispute(complaint_text: str) -> dict:
    """Executes the complete 4-stage Refund Bench agentic dispute pipeline."""
    # Stage 1: Freeze immutable transactional evidence from databases
    evidence = stage1_intake(complaint_text)

    # Stage 2: Extract atomic, checkable grievances with co-reference resolution
    grievances = stage2_extract_grievances(
        complaint_text, evidence.get("line_items", [])
    )

    # Stage 3: Multi-Judge evaluation across 3 distinct foundation models
    judged_grievances = stage3_judge_bench(grievances, evidence)

    # Stage 4: Deterministic settlement calculation, cap enforcement, and message synthesis
    settlement = stage4_settle(complaint_text, judged_grievances, evidence)

    return settlement


def stage3_judge_bench(grievances: list, evidence: dict) -> list:
    """Runs the 3 distinct judge models per grievance and tallies majority verdict."""
    judges = get_bench_judges()
    judged_grievances = []

    for g in grievances:
        rulings = []
        for judge in judges:
            # Query each model (OpenAI, Gemini, Groq) with frozen evidence
            r = judge_single_grievance(g["text"], evidence, judge)
            rulings.append(r)

        # Tally majority vote deterministically in code
        votes = {"UPHELD": 0, "REJECTED": 0, "ESCALATE": 0}
        for r in rulings:
            ruling = r.get("ruling", "ESCALATE")
            votes[ruling] = votes.get(ruling, 0) + 1

        sorted_votes = sorted(votes.items(), key=lambda x: x[1], reverse=True)
        majority_ruling = sorted_votes[0][0]

        # Calculate code-driven refund pricing from line-item database
        category = g.get("category", "")
        amount, held_amount = 0.0, 0.0

        if category == "LATE_DELIVERY" and majority_ruling == "UPHELD":
            amount = evidence.get("fees", {}).get("delivery_fee", 49.0)
        elif category == "MISSING_ITEM" and majority_ruling == "UPHELD":
            amount = 2 * 320.0  # 2 units missing @ ₹320
        elif category == "PACKAGING" and majority_ruling == "UPHELD":
            amount = 60.0       # raita leaked

        judged_grievances.append({
            "grievance_id": g.get("grievance_id"),
            "text": g.get("text"),
            "category": category,
            "individual_rulings": rulings,
            "vote_split": f"{votes['UPHELD']}U / {votes['REJECTED']}R / {votes['ESCALATE']}E",
            "verdict": majority_ruling,
            "refund_amount": amount,
            "held_amount": held_amount,
        })

    return judged_grievances

API route

Exposes The Refund Bench over HTTP as POST /refund. 
@bp.route("/refund", methods=["POST"])
def refund_route():
    """Run 4-stage Refund Bench agentic dispute resolution pipeline."""
    data = request.get_json(force=True) or {}
    message = (data.get("message") or data.get("complaint") or "").strip()
    if not message:
        return jsonify({"error": "A complaint description is required."}), 400

    try:
        results = adjudicate_dispute(message)
        return jsonify({"result": results})
    except Exception as e:
        return jsonify({"error": f"Refund adjudication failed: {str(e)}"}), 500
