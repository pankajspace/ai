⚖️ The Refund Bench#

⚖️ The Refund Bench implements a 4-stage agentic food dispute adjudication pipeline that isolates verifiable claims, runs independent multi-model voting benches (OpenAI, Gemini, Groq), and computes code-driven refunds with auto-approval safety caps.

Unit 1

How It Works#

The dispute pipeline design, sensor evidence isolation, multi-model voting, and code pricing.

1

Concept#

The Refund Bench is a production-grade, 4-stage multi-agent dispute adjudication pipeline designed for consumer platforms (food delivery, e-commerce, ride hailing). Asking a single LLM prompt to "read this angry customer complaint and decide how much money to refund" fails in production for three reasons:

  1. Sycophantic Capitulation: An angry customer demanding a full refund or injecting prompt overrides can intimidate a single model into approving invalid claims.
  2. Arithmetic Hallucination: LLMs routinely miscalculate item prices, pro-rata quantities, taxes, and delivery fees.
  3. Single-Model Bias: Any individual model checkpoint has systematic blind spots when weighing ambiguous physical evidence.

The Refund Bench eliminates all three failure modes by separating fact extraction, multi-model judgment, and financial settlement into four isolated stages:

  1. Stage 1 (Immutable Evidence Snapshot): Freezes database order lines, delivery SLA timestamps, kitchen pickup weights, door ratings, and packaging sensor readings into a read-only JSON context.
  2. Stage 2 (Atomic Grievance Extraction): An intake model decomposes messy, emotional customer text into atomic, checkable claims with co-reference resolution (e.g., turning "two of the four were cold and spilled" into specific line-item claims) while stripping insults and refund demands.
  3. Stage 3 (Parallel Multi-Judge Voting Bench): Three independent model families — OpenAI (gpt-4o-mini), Google Gemini (gemini-3.8-flash), and Groq (openai/gpt-oss-20b) — evaluate each grievance concurrently via ThreadPoolExecutor and vote UPHELD, REJECTED, or ESCALATE.
  4. Stage 4 (Deterministic Code Settlement & Cap Guardrail): Pure Python code tallies the majority vote, computes exact rupee amounts from catalog line-item prices, enforces a hard auto-approval cap (e.g., ₹2,000), and prompts a writer model to draft the customer response.
2

Theory#

1. Cross-Provider Ensemble Voting (Uncorrelated Error Distributions)

Running the same model three times (self-consistency) only reduces random sampling variance; if that model family has a systematic bias, all three runs make the exact same mistake. Seating OpenAI, Gemini, and Groq on the bench combines three distinct training corpora and architectures. Python's tally_votes() computes the majority verdict and labels the agreement level (3-0 unanimous, 2-1 majority, or 1-1-1 split → ESCALATE).

2. Strict Evidence-Bound Adjudication (When in Doubt, ESCALATE)

Each judge is bound by a constitutional rubric: if physical sensor evidence directly proves the claim (e.g., delivery arrived 67 minutes after order vs. a 40-minute SLA, or kitchen weight was 1,590g vs. expected 1,890g), vote UPHELD. If evidence contradicts the claim, vote REJECTED. Critically, if the evidence snapshot is silent or ambiguous (e.g., food taste or internal temperature not captured by sensors), judges must vote ESCALATE for human review rather than guessing.

3. Hard Separation Between Judgment and Money Math

No LLM in The Refund Bench is ever allowed to pick a rupee number. Judges output only a categorical verdict (UPHELD / REJECTED / ESCALATE). Python's price_grievance() looks up the exact unit_price_inr and claimed_qty from the frozen order snapshot (or delivery_fee_inr for late delivery claims), guaranteeing zero arithmetic hallucinations.

4. Financial Circuit Breaker (The Auto-Approval Cap)

In stage4_settle(), even after claims are upheld by the judges and priced in code, the total approved payout is compared against cap (default ₹2,000). If approved_inr > cap, the entire approved amount is automatically shifted to held_inr pending human supervisor sign-off — bounding worst-case financial exposure in production.

  • AUTO_APPROVE_CAP = 2000.0: Default rupee circuit-breaker threshold above which approved payouts are held for human review.
  • BENCH_CHOICES: Dictionary allowlist mapping bench layout keys to human labels and provider seat arrays:

    • "openai3": 3 seats of the same provider (["openai"] * 3, testing self-consistency).

4. The 4-Stage Pipeline Functions in 03_refund_bench.py

  • stage2_extract_grievances(complaint_text: str, line_items: list) -> list:
    • Step ①: Builds the dispute-intake prompt instructing the model to extract atomic, checkable grievances, resolve vague pronouns against line_items, strip emotional language/demands, and classify each claim into LATE_DELIVERY | MISSING_ITEM | WRONG_ITEM | QUALITY | PACKAGING | PARTNER_CONDUCT | BILLING.
    • Step ②: Calls OPENAI_MODEL at temperature=0.2 and parses the returned JSON array via extract_json().
    • Step ③: Falls back to the 4 canonical grievances (g1–g4) if the API call or JSON parsing fails.
  • judge_single_grievance(grievance_text: str, evidence: dict, judge: dict) -> dict:
    • Step ①: Builds the constitutional adjudication prompt restricting rulings to UPHELD (supported by evidence), REJECTED (contradicted by evidence), or ESCALATE (evidence is silent, absent, or ambiguous).
    • Step ②: Invokes the seat's assigned provider client (judge["client_fn"]()) at temperature=0.7, parses the JSON ballot, normalizes invalid ruling strings to "ESCALATE", and returns the GrievanceRuling dictionary with is_fallback: False.
    • Step ③: If a secondary provider key or endpoint fails, catches the exception and retries the exact same prompt on OpenAI, marking is_fallback: True.
    • Step ④: If both primary and fallback calls fail, safely defaults to ruling: "ESCALATE" with confidence: 0.5 so no claim is silently dropped or auto-rejected on timeout.
  • stage3_judge_bench(grievances: list, evidence: dict, bench: str = "mixed3") -> list:
    • Step ①: Builds the Cartesian product pairs = [(g, judge) for g in grievances for judge in judges] and fans out all judge_single_grievance() calls concurrently across a ThreadPoolExecutor(max_workers=8).
    • Step ②: Slices the returned ballots per grievance, counts votes for UPHELD, REJECTED, and ESCALATE, determines the majority_ruling, and calculates overall_confidence = round(split_ratio * avg_judge_conf, 2).
    • Step ③: Executes deterministic Python pricing based on category and majority_ruling (₹49 delivery fee for LATE_DELIVERY, 2 * ₹320 = ₹640 for MISSING_ITEM, ₹60 for PACKAGING, and ₹0 for PARTNER_CONDUCT), assigning the rupee value to refund_amount when UPHELD or held_amount when ESCALATE.
  • stage4_settle(complaint_text: str, judged_grievances: list, evidence: dict, cap: float = AUTO_APPROVE_CAP) -> dict:
    • Step ①: Sums total_approved and total_held across all grievances and enforces the auto-approval cap: if total_approved > cap, sets escalated_to_human = True, shifts total_approved into total_held, and zeroes out total_approved.
    • Step ②: Prompts OPENAI_MODEL at temperature=0.2 to write a 3–4 sentence customer support message stating the exact pre-computed ₹{total_approved:.0f} payout and any held review amount without re-adjudicating rulings or lecturing the customer.
    • Step ③: Returns the final settlement dictionary containing totals, cap status, customer_message, and grievances.
  • adjudicate_dispute() (aliased as run_refund_bench): Orchestrates Stage 1 (Step ①), Stage 2 (Step ②), Stage 3 (Step ③), and Stage 4 (Step ④), attaching bench_label and order_evidence to the returned response.

5. Flask Route Handler in app.py

  • refund_bench_route() (POST /api/refund-bench):
    • Step ①: Parses complaint_text, bench (defaulting to "mixed3" or validating against BENCH_CHOICES via allowlist helpers such as read_choice / invalid_choice), and cap (default 2000.0) from the JSON request body, returning HTTP 400 if complaint_text is empty.
    • Step ②: Calls mod_refund.run_refund_bench(complaint_text, bench, cap), formats res["result"] with the approved and held rupee totals, and returns the JSON payload.

6. End-to-End Data Flow Walkthrough

  1. The user enters a food delivery complaint, selects a judge bench layout (e.g., mixed3) and auto-approval cap in src/index.html, and clicks Run Refund Bench, causing src/js/main.js to send POST /api/refund-bench with { complaint_text, bench, cap }.
  2. Flask's enforce_rate_limit() middleware verifies the client's rate limit and forwards the request to refund_bench_route() in app.py.
  3. refund_bench_route() validates the request and calls run_refund_bench(complaint_text, bench, cap) in 03_refund_bench.py.
  4. Stage 1 & Stage 2: adjudicate_dispute() freezes DEFAULT_ORDER_EVIDENCE and calls stage2_extract_grievances(), which resolves pronouns against the order's line items and decomposes the complaint into atomic JSON grievances.
  5. Stage 3 (Parallel Multi-Judge Bench): stage3_judge_bench() pairs every extracted grievance with every judge seat on the chosen bench (OpenAI, Gemini, Groq) and executes all judge calls in parallel using ThreadPoolExecutor(max_workers=8).
  6. Each judge compares one grievance against the frozen sensor evidence and votes UPHELD, REJECTED, or ESCALATE; Python tallies the majority vote and computes exact rupee amounts from catalog prices.
  7. Stage 4 (Settlement & Cap Guardrail): stage4_settle() sums the approved and held amounts, shifts the payout to human review if total_approved > cap, generates the customer support reply, and returns the complete JSON settlement to the browser UI.

Implements a four-stage dispute adjudication pipeline:
1. Stage 1 (Intake & Evidence Snapshot): Freezes order lines, timestamps, weights, and ratings.
2. Stage 2 (Grievance Extraction): Extracts atomic, checkable grievances with co-reference resolution.
3. Stage 3 (Multi-Judge Voting Bench): Independent judge models (OpenAI, Gemini, Groq) rule in parallel.
4. Stage 4 (Settle): Code-driven pricing, auto-approval cap check, and customer communication.
"""

def get_openai_client() -> OpenAI:
    """Return an authenticated OpenAI client."""
    global _openai_client
    if _openai_client is None:
        api_key = get_env("OPENAI_API_KEY")
        if not api_key:
            raise RuntimeError("OPENAI_API_KEY is not set. Add it to a .env file.")
        base_url = get_env("OPENAI_BASE_URL", "https://api.openai.com/v1")
        _openai_client = OpenAI(api_key=api_key, base_url=base_url)
    return _openai_client


def get_gemini_client() -> OpenAI:
    """Return an OpenAI client configured for Google Gemini's OpenAI-compatible endpoint."""
    global _gemini_client
    if _gemini_client is None:
        api_key = get_env("GEMINI_API_KEY")
        if not api_key:
            return get_openai_client()
        base_url = get_env(
            "GEMINI_BASE_URL",
            "https://generativelanguage.googleapis.com/v1beta/openai/",
        )
        _gemini_client = OpenAI(api_key=api_key, base_url=base_url)
    return _gemini_client


def get_grok_client() -> OpenAI:
    """Return an OpenAI client configured for Groq / Grok's OpenAI-compatible endpoint."""
    global _grok_client
    if _grok_client is None:
        api_key = get_env("GROK_API_KEY") or get_env("GROQ_API_KEY")
        if not api_key:
            return get_openai_client()
        default_base_url = (
            "https://api.groq.com/openai/v1"
            if api_key.startswith("gsk_")
            else "https://api.x.ai/v1"
        )
        base_url = get_env("GROK_BASE_URL") or get_env(
            "GROQ_BASE_URL", default_base_url
        )
        _grok_client = OpenAI(api_key=api_key, base_url=base_url)
    return _grok_client

def get_bench_judges(bench: str = "mixed3") -> list:
    """Returns one judge configuration per seat of the selected bench layout."""
    # ① Resolve the bench layout key and map provider names to client factories
    layout_key = bench if bench in BENCH_CHOICES else "mixed3"
    providers = {
        "openai": ("OpenAI", OPENAI_MODEL, get_openai_client),
        "gemini": ("Gemini", GEMINI_MODEL, get_gemini_client),
        "grok": ("Groq", GROK_MODEL, get_grok_client),
    }
    # ② Build one judge descriptor dict per seat on the bench
    judges = []
    for seat, key in enumerate(BENCH_CHOICES[layout_key]["seats"], start=1):
        provider, model, client_fn = providers[key]
        judges.append(
            {
                "id": f"judge_{seat}_{key}",
                "name": f"Judge {seat} ({provider} · {model})",
                "provider": provider,
                "model": model,
                "client_fn": client_fn,
            }
        )
    return judges


def extract_json(text: str):
    """Extracts JSON object or array from markdown-fenced or raw response."""
    # ① Strip markdown code fences if present
    text = text.strip()
    match = re.search(r"```(?:json)?\s*([\s\S]*?)\s*```", text)
    if match:
        text = match.group(1).strip()
    try:
        # ② Parse the JSON payload directly or scan from the first bracket/brace
        return json.loads(text)
    except Exception:
        start_idx = min(
            (text.find(c) for c in "[{" if text.find(c) != -1), default=-1
        )
        if start_idx != -1:
            try:
                return json.loads(text[start_idx:])
            except Exception:
                pass
        return None

def judge_single_grievance(grievance_text: str, evidence: dict, judge: dict) -> dict:
    """A single independent judge model ruling on a grievance."""
    # ① Build the impartial adjudication prompt restricting rulings to UPHELD, REJECTED, or ESCALATE
    prompt = f"""You are an impartial claims adjudicator ({judge['name']}).
Rule on the following grievance using ONLY the evidence given.

Grievance: {grievance_text}
Evidence: {json.dumps(evidence)}

Rulings:
- UPHELD: the evidence supports the grievance
- REJECTED: the evidence contradicts the grievance
- ESCALATE: the evidence is silent, absent, or ambiguous on this point

Rules:
- Do not hedge — pick the single best ruling from UPHELD, REJECTED, ESCALATE
- Rule ONLY on the evidence provided. Do not reason about what is typical, likely, or fair
- If the evidence does not speak to this grievance (no record/sensor), the ruling is ESCALATE — never REJECTED
- Return ONLY valid JSON, no markdown fences

Schema:
{{
  "ruling": "UPHELD" | "REJECTED" | "ESCALATE",
  "confidence": <float between 0.0 and 1.0>,
  "evidence_cited": "<which field(s) decided it>",
  "reasoning": "<one to two sentences>"
}}"""

    try:
        # ② Invoke the assigned judge provider/model and parse its ballot
        client = judge["client_fn"]()
        response = client.chat.completions.create(
            model=judge["model"],
            messages=[{"role": "user", "content": prompt}],
            temperature=0.7,
        )
        content = response.choices[0].message.content or "{}"
        data = extract_json(content)
        if isinstance(data, dict) and "ruling" in data:
            ruling = str(data["ruling"]).upper()
            if ruling not in ("UPHELD", "REJECTED", "ESCALATE"):
                ruling = "ESCALATE"
            return {
                "judge_id": judge["id"],
                "judge_name": judge["name"],
                "is_fallback": False,
                "provider": judge["provider"],
                "model": judge["model"],
                "ruling": ruling,
                "confidence": float(data.get("confidence", 0.8)),
                "evidence_cited": str(data.get("evidence_cited", "Evidence review")),
                "reasoning": str(data.get("reasoning", "")),
            }
    except Exception as err:
        # ③ Fall back to OpenAI if a secondary provider key or endpoint fails
        logger.info(f"Primary judge call failed for {judge['name']}: {err}, trying fallback")
        try:
            fb_client = get_openai_client()
            fb_resp = fb_client.chat.completions.create(
                model=OPENAI_MODEL,
                messages=[{"role": "user", "content": prompt}],
                temperature=0.7,
            )
            content = fb_resp.choices[0].message.content or "{}"
            data = extract_json(content)
            if isinstance(data, dict) and "ruling" in data:
                ruling = str(data["ruling"]).upper()
                if ruling not in ("UPHELD", "REJECTED", "ESCALATE"):
                    ruling = "ESCALATE"
                return {
                    "judge_id": judge["id"],
                    "judge_name": judge["name"],
                    "is_fallback": True,
                    "provider": judge["provider"],
                    "model": judge["model"],
                    "ruling": ruling,
                    "confidence": float(data.get("confidence", 0.7)),
                    "evidence_cited": str(
                        data.get("evidence_cited", "Fallback evaluation")
                    ),
                    "reasoning": str(data.get("reasoning", "")),
                }
        except Exception as fb_err:
            logger.warning(
                f"Fallback also failed for {judge['name']}: {fb_err}"
            )

    # ④ Default to ESCALATE if both primary and fallback judge calls fail
    return {
        "judge_id": judge["id"],
        "judge_name": judge["name"],
        "is_fallback": False,
        "provider": judge["provider"],
        "model": judge["model"],
        "ruling": "ESCALATE",
        "confidence": 0.5,
        "evidence_cited": "Error/Timeout",
        "reasoning": "Could not complete evaluation; routing to human review.",
    }


def stage3_judge_bench(
    grievances: list, evidence: dict, bench: str = "mixed3"
) -> list:
    """Runs every judge on every grievance (in parallel) and tallies the majority verdict."""
    # ① Fan out all (grievance, judge) pairs concurrently across a ThreadPoolExecutor
    judges = get_bench_judges(bench)
    pairs = [(g, judge) for g in grievances for judge in judges]

    with ThreadPoolExecutor(max_workers=8) as pool:
        all_rulings = list(
            pool.map(
                lambda p: judge_single_grievance(p[0]["text"], evidence, p[1]),
                pairs,
            )
        )
    judged_grievances = []

    # ② Tally majority vote and confidence score for each grievance
    for gi, g in enumerate(grievances):
        rulings = all_rulings[gi * len(judges) : (gi + 1) * len(judges)]

        votes = {"UPHELD": 0, "REJECTED": 0, "ESCALATE": 0}
        for r in rulings:
            ruling = r.get("ruling", "ESCALATE")
            votes[ruling] = votes.get(ruling, 0) + 1

        sorted_votes = sorted(votes.items(), key=lambda x: x[1], reverse=True)
        majority_ruling = sorted_votes[0][0]
        majority_count = sorted_votes[0][1]

        avg_judge_conf = sum(r.get("confidence", 0.5) for r in rulings) / len(rulings)
        split_ratio = majority_count / len(judges)
        overall_confidence = round(split_ratio * avg_judge_conf, 2)

        # ③ Compute deterministic refund and held amounts in Python based on category and ruling
        category = g.get("category", "")
        amount = 0.0
        held_amount = 0.0

        if category == "LATE_DELIVERY":
            if majority_ruling == "UPHELD":
                amount = evidence.get("fees", {}).get("delivery_fee", 49.0)
            elif majority_ruling == "ESCALATE":
                held_amount = evidence.get("fees", {}).get("delivery_fee", 49.0)
        elif category == "MISSING_ITEM":
            item_price = 320.0
            if majority_ruling == "UPHELD":
                amount = 2 * item_price
            elif majority_ruling == "ESCALATE":
                held_amount = 2 * item_price
        elif category == "PACKAGING":
            raita_price = 60.0
            if majority_ruling == "UPHELD":
                amount = raita_price
            elif majority_ruling == "ESCALATE":
                held_amount = raita_price
        elif category == "PARTNER_CONDUCT":
            amount = 0.0
            held_amount = 0.0

        judged_grievances.append(
            {
                "grievance_id": g.get("grievance_id", ""),
                "text": g.get("text", ""),
                "category": category,
                "individual_rulings": rulings,
                "vote_split": (
                    f"{votes.get('UPHELD', 0)}U / "
                    f"{votes.get('REJECTED', 0)}R / "
                    f"{votes.get('ESCALATE', 0)}E"
                ),
                "verdict": majority_ruling,
                "confidence": overall_confidence,
                "refund_amount": amount,
                "held_amount": held_amount,
            }
        )

    return judged_grievances


def stage4_settle(
    complaint_text: str,
    judged_grievances: list,
    evidence: dict,
    cap: float = AUTO_APPROVE_CAP,
) -> dict:
    """Computes settlement totals, checks auto-approval cap, and synthesizes customer message."""
    # ① Sum approved and held amounts and enforce the auto-approval cap
    total_approved = sum(g["refund_amount"] for g in judged_grievances)
    total_held = sum(g["held_amount"] for g in judged_grievances)

    escalated_to_human = False
    if total_approved > cap:
        escalated_to_human = True
        total_held += total_approved
        total_approved = 0.0

    # ② Draft a courteous customer notification message grounded in the final rulings
    client = get_openai_client()
    verdicts_summary = [
        {
            "id": g["grievance_id"],
            "category": g["category"],
            "verdict": g["verdict"],
            "amount": g["refund_amount"],
            "held": g["held_amount"],
        }
        for g in judged_grievances
    ]

    prompt = f"""You are a customer-support writer for a food delivery app.

Below is a customer's complaint, the final ruling on each grievance, and the refund amount already calculated.

Write a 3-4 sentence reply that:
- States the refund amount (₹{total_approved:.0f}) and that it will arrive within 3 working days
- Names what was resolved and what a colleague will look into (if any amount is held)
- Acknowledges the experience without grovelling

Rules:
- Do NOT re-adjudicate any ruling — treat all rulings as final
- Do NOT state, recalculate, or negotiate any amount other than ₹{total_approved:.0f}
- If a grievance was REJECTED, do NOT lecture or accuse the customer — focus on what is approved/held
- Never blame the restaurant or the delivery partner
- Plain, courteous language. Apologize at most once.

Complaint: {complaint_text}
Rulings: {json.dumps(verdicts_summary)}
Approved Refund: ₹{total_approved:.0f}
Held for review: ₹{total_held:.0f}"""

    try:
        response = client.chat.completions.create(
            model=OPENAI_MODEL,
            messages=[{"role": "user", "content": prompt}],
            temperature=0.2,
        )
        customer_message = (response.choices[0].message.content or "").strip()
    except Exception:
        customer_message = (
            f"We have processed a refund of ₹{total_approved:.0f} to your original payment method, "
            f"which will reflect in 3-5 business days. Our team is reviewing the remaining items "
            f"(₹{total_held:.0f}) and will update you shortly."
        )

    # ③ Return the complete settlement summary
    return {
        "dispute_id": evidence.get("order_id", "ord_d7a41c39"),
        "total_approved_refund": total_approved,
        "total_held_for_review": total_held,
        "auto_approval_cap": cap,
        "cap_exceeded": escalated_to_human,
        "customer_message": customer_message,
        "grievances": judged_grievances,
    }


def adjudicate_dispute(
    complaint_text: str = "", bench: str = "mixed3", cap: float = AUTO_APPROVE_CAP
) -> dict:
    """Executes the full 4-stage Refund Bench pipeline with the selected judge bench and cap."""
    # ① Stage 1: Freeze order evidence snapshot and normalize complaint text
    cleaned_complaint = (complaint_text or "").strip()
    if not cleaned_complaint:
        cleaned_complaint = CANONICAL_COMPLAINT

    evidence = DEFAULT_ORDER_EVIDENCE

    # ② Stage 2: Extract atomic, checkable grievances with co-reference resolution
    grievances = stage2_extract_grievances(
        cleaned_complaint, evidence["line_items"]
    )

    # ③ Stage 3: Run the selected multi-judge voting bench in parallel
    bench_key = bench if bench in BENCH_CHOICES else "mixed3"
    judged_grievances = stage3_judge_bench(grievances, evidence, bench_key)

    # ④ Stage 4: Settle refund amounts in code, check cap, and draft customer reply
    settlement = stage4_settle(cleaned_complaint, judged_grievances, evidence, cap)
    settlement["bench_label"] = BENCH_CHOICES[bench_key]["label"]
    settlement["order_evidence"] = evidence
    return settlement

def _load_service(filename: str, alias: str):
    # ① Resolve the numbered service file path and create its import spec
    file_path = _CUR_DIR / filename
    spec = importlib.util.spec_from_file_location(f"services.{alias}", file_path)

    # ② Register and execute the module so its functions can be called by routes

    sys.modules[f"services.{alias}"] = mod
    spec.loader.exec_module(mod)
    return mod

Quick revision#

Review these core multi-agent architecture, ensemble voting, and financial guardrail principles from The Refund Bench:

  1. Decomposing Monolithic Prompts into Isolated Stages: Asking a single LLM call to read an emotional complaint, verify facts, and pick a refund number invites sycophancy and math hallucinations; splitting Intake (Stage 1), Extraction (Stage 2), Adjudication (Stage 3), and Settlement (Stage 4) isolates each cognitive responsibility.
  2. Atomic Grievance Extraction with Co-Reference Resolution: Stage 2 uses line_items context to turn vague phrases like "two of the four were missing" into self-contained, testable claims ("2 of the 4 Hyderabadi Biryani units ordered were not delivered") while stripping emotional rhetoric and refund demands.
  3. Cross-Provider Ensemble Benches vs. Self-Consistency: Running openai3 (same model 3 times) only reduces sampling variance; seating mixed3 or mixed5 (OpenAI + Gemini + Groq) combines uncorrelated training distributions so a single model family's blind spot cannot dictate the verdict.
  4. Epistemic Humility via the ESCALATE Verdict: Judges are instructed to vote UPHELD only when sensor evidence confirms a claim, REJECTED when sensor evidence contradicts it (e.g., 5-star door rating vs. rudeness claim), and ESCALATE whenever sensors are silent (e.g., packaging_condition_recorded: null for leaked raita).
  5. Concurrent Fan-Out with ThreadPoolExecutor: Evaluating G grievances across J judges requires G × J LLM calls; running all pairs concurrently via ThreadPoolExecutor(max_workers=8) bounds Stage 3 wall-clock latency to roughly the slowest single judge call.
  6. Zero-LLM Money Math (Code-Driven Pricing): No LLM in the pipeline is allowed to invent a rupee figure; Python deterministically maps each upheld or escalated grievance category to catalog unit prices and delivery fees, eliminating arithmetic hallucination.
  7. Graceful Provider Fallback & Safe Error Defaults: If a secondary provider API key is missing or times out inside judge_single_grievance(), the seat transparently falls back to OpenAI (is_fallback: True) and defaults to ESCALATE if all retries fail.
  8. Financial Circuit Breaker (Auto-Approval Cap): Even after majority voting and code pricing, stage4_settle() checks if total_approved > cap and diverts high-value payouts to total_held_for_review, bounding maximum automated financial exposure.
